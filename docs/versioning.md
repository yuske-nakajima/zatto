# バージョニング方針

zatto は [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html) に従います。
`package.json` の `version` がバージョンの正本です。

この方針は採用後のリリースに適用します。公開済みのバージョンやタグは変更しません。

## 公開契約

バージョン判断では、次の項目を公開契約として扱います。

- CLI のコマンド、オプション、終了状態、利用者が依存する出力と挙動
- ブラウザー UI の機能と利用者が依存する挙動
- `@yuske-nakajima/zatto/server` が公開する関数、型、実行方法
- HTTP API、WebSocket、runtime record の互換性に関わる形式
- セッション交換形式と永続データ形式
- 対応する Node.js、OS、ブラウザーなどの実行環境
- README に記載する利用方法と保証

内部実装でも、公開契約へ観測可能な影響があれば、その影響に基づいて判断します。

## リリース要否

公開パッケージ、公開契約、利用者向け文書のいずれかへ影響する PR はリリース対象です。

次の変更だけで構成する PR は、リリースなしとしてバージョン更新を省略できます。

- 公開物へ影響しない CI や依存性チェックの設定
- テストだけの追加または整理
- `.claude/` など開発支援ルールだけの変更
- 公開物へ影響しない開発用スクリプトの変更
- コントリビューター向け文書だけの変更

リリース対象の変更を1つでも含む場合、この例外は適用しません。
リファクタリングで配布コードが変わる場合も、後方互換な変更としてリリースします。

## `0.x` の判断基準

`0.x` は初期開発期間です。互換性は保証しませんが、変更の意味をバージョンで伝えます。

| 種別 | 基準 | 例 |
|---|---|---|
| minor | 利用者向け機能の追加 | HTML 検索、セッションのインポートとエクスポート |
| minor | 公開契約の非互換な変更 | CLI オプションの削除、セッション形式の非互換な変更 |
| patch | 後方互換な不具合修正 | IME で日本語を入力できない問題の修正 |
| patch | 公開物に含まれる文書の修正 | README の利用方法や制約の訂正 |
| patch | 後方互換な内部変更 | 配布コードのリファクタリング、ビルド結果の修正 |
| patch | リリース対象に含まれるテストや内部ツールの変更 | 公開物の変更に伴うテスト、公開処理の修正 |

minor を上げるときは patch を `0` に戻します。
たとえば `0.1.6` に機能を追加する場合は `0.2.0` です。
`0.1.6` の後方互換な不具合修正は `0.1.7` です。

`1.0.0` は minor の繰り上がりではありません。
公開契約を安定版として維持する明示的な決定をしたときに限り、`1.0.0` を公開します。

## `1.x` 以降の判断基準

| 種別 | 基準 |
|---|---|
| major | 公開契約の非互換な変更 |
| minor | 後方互換な利用者向け機能の追加、公開 API の非推奨化 |
| patch | リリース対象となる後方互換な修正、文書、テスト、リファクタリング、内部ツールの変更 |

minor を上げるときは patch を `0` に戻します。
major を上げるときは minor と patch を `0` に戻します。

## 複数の変更と依存関係

複数種の変更を含む PR では、最も影響が大きい変更に合わせます。
`0.x` では minor が patch より大きく、`1.x` 以降では major、minor、patch の順です。

依存関係の更新は、利用者が観測できる影響で分類します。
機能追加なら機能追加、非互換な変更なら非互換な変更として扱います。
修正や保守だけでリリースする場合は patch です。
セキュリティ修正を公開する場合は、少なくとも patch を上げます。

## PR での更新手順

1. 最新の `main` にある `package.json` のバージョンを基準にする。
2. PR 全体を分類し、リリース要否と変更種別を決める。
3. PR 作成前に `package.json` の `version` を1回だけ更新する。
4. 固定バージョンを持つテストとスクリプトを同じ値へ同期する。
5. 品質チェックとパッケージ検証を実行する。

「1回だけ」は、同じ PR の変更を理由に段階的な加算を繰り返さないことを意味します。
PR への変更追加でも、すでに選んだバージョンから再加算しません。

`main` のバージョンが競合で進んだ場合は、最新の `main` を新しい基準にします。
その基準へ PR の変更種別を適用し、最終値を置き換えます。

固定バージョンは、少なくとも次のファイルで同期します。

- `scripts/verify-package.mjs`
- `test/package.test.ts`

## zatto の例

- ページ内検索で IME 入力を受け付ける修正: patch
- 新しい検索方式やセッション操作の追加: minor（`0.x`）、minor（`1.x` 以降）
- `@yuske-nakajima/zatto/server` の後方互換な API 追加: minor
- CLI オプションや公開サーバー API の削除: minor（`0.x`）、major（`1.x` 以降）
- セッション交換形式を後方互換なしで変更: minor（`0.x`）、major（`1.x` 以降）
- README の誤りだけを訂正して公開する変更: patch
- CI 設定やテストだけを変更し、公開物に影響しない PR: リリースなし
