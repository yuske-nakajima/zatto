JSON-RPC API

全35操作はPOST /rpcへapplication/jsonで送信します。2.0.0でREST操作ルートを廃止し、静的配信とWebSocket通知は維持します。

要求と応答

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "session.get",
  "params": {}
}
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "session.setFavorite",
  "params": {
    "id": "entry-id",
    "favorite": true,
    "workspaceId": "default"
  }
}
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": null
}

引数は名前付きのオブジェクトです。paramsの省略は空オブジェクトを表します。IDは文字列、数値、nullを受け取り、応答は同じIDとresultまたはerrorの一方を返します。完了を確認する操作にはID付き要求を使います。

対象ワークスペースと識別子

ファイルを変更・エクスポートする操作は、操作の対象であるworkspaceIdを必須とします。選択中かどうかにかかわらず任意のワークスペースを指定でき、選択状態は変わりません。存在しない、または削除されたワークスペースはワークスペースのエラーを返します。agentContext.setもworkspaceIdを必須とし、ブラウザーの状態は選択中のワークスペースに属するため、選択中と異なる場合は拒否します。非同期処理の前に対象を捕捉します。

server.health以外は任意のinstanceIdを照合条件として受け取ります。ネイティブ選択ではinstanceIdが必須で、管理対象のインポートと停止でも必要です。

メソッド

server.health

サーバーの名前、配布版、識別子、通信バージョンを取得します。

params: {}
result: { name, version, instanceId?, protocolVersion? }

server.shutdown

管理対象ではinstanceIdを照合し、単体またはbatchの応答完了後に停止します。

params: { instanceId? }
result: { ok: true }

session.get

選択中の一覧、ワークスペース情報、ネイティブ選択機能を取得します。外の端末から呼んだときはaccess: "remote"を返し、entriesのabsPathはファイル名だけになり、ネイティブ選択は使えません。

params: {}
result: { access, entries, activeWorkspaceId, workspaces, serverIdentity?, filePicker, directoryPicker }

session.add

パスを絶対パスへ解決し、既存・追加エントリを指定順で1回ずつ返します。存在しないパスは除外し、読取り・保存失敗時は追加全体を確定しません。HTMLの拡張子は必須ではありません。

params: { workspaceId: string, paths: string[] }
result: { added, resolved, workspaceId, activeWorkspaceId, session }

session.setFavorite

星を明示的な真偽値で保存します。並び順を変更せず、同じ値の再指定では保存も通知もしません。

params: { workspaceId: string, id: string, favorite: boolean }
result: null

session.reorder

対象ワークスペースの全エントリIDを、希望するList順で重複なく1回ずつ指定します。

params: { workspaceId: string, ids: string[] }
result: null

session.reorderFavorites

対象ワークスペースのお気に入りのIDを、希望するFavoritesの順で重複なく1回ずつ指定します。お気に入りの順はList順とは別に保存し、List順は変えません。新しくお気に入りにしたファイルは、お気に入りの順の末尾に加わります。エントリのfavoriteRankがお気に入りの順を表します。

params: { workspaceId: string, ids: string[] }
result: null

session.removeMany

空でない既知のIDを重複なく指定し、一覧から原子的に外します。実ファイルは残します。

params: { workspaceId: string, ids: string[] }
result: null

session.remove

指定したエントリを一覧から外し、実ファイルは残します。

params: { workspaceId: string, id: string }
result: null

session.clear

対象の一覧を空にし、実ファイルは残します。

params: { workspaceId: string }
result: null

session.export

対象ワークスペースの表示順の絶対パスをzatto-sessionのversion 1形式で返します。

params: { workspaceId: string }
result: SessionExchange version 1

session.import

全パスを検証してから確定します。既定のreplaceは全置換と星のリセット、mergeは既存エントリと星を保持した追加です。管理対象ではinstanceIdが必要です。

params: { workspaceId: string, exchange, mode?: "replace" | "merge", instanceId? }
result: { entries }

session.pickFiles

ネイティブファイル選択を開きます。instanceIdを照合し、キャンセル時は変更しません。対象のワークスペースへ追加します。

params: { workspaceId: string, instanceId: string }
result: { cancelled, added, session? }

session.pickDirectory

選択したフォルダーの直下、または子孫のHTMLとMarkdownを追加します。ネイティブ選択は同時に1つだけ開き、シンボリックリンクはたどりません。

params: { workspaceId: string, instanceId: string, mode: "direct" | "recursive" }
result: { cancelled, added, session? }

workspaces.list

名前と識別子、全タブで共有する選択状態を取得します。

params: {}
result: { activeWorkspaceId, workspaces: [{ id, name }] }

workspaces.get

選択状態を変えずに、指定したワークスペースの名前とList順のエントリを取得します。存在しない識別子はワークスペースのエラーを返します。

params: { id: string }
result: { id, name, entries }

workspaces.create

選択を変えず空のワークスペースを作成します。前後の空白を除いた名前は1〜100文字です。

params: { name: string }
result: { id, name }

workspaces.activate

選択を保存して通知します。ブラウザーの検索とプレビューはワークスペース切替時の規則に従います。

params: { id: string }
result: { entries, activeWorkspaceId, workspaces }

workspaces.rename

ファイル群と識別子を維持して名前を変更します。

params: { id: string, name: string }
result: { activeWorkspaceId, workspaces }

workspaces.delete

実ファイルを残して削除します。最低1件を維持し、選択中の削除では残る先頭へ切り替えます。

params: { id: string }
result: { entries, activeWorkspaceId, workspaces }

agentContext.get

本文を含めずタイトルと絶対パスを返します。タイトルは信頼できないラベルとして正規化し、Unicodeコードポイントで200文字へ制限します。

params: {}
result: { schemaVersion: 1, activeFile, openFiles, view }

agentContext.set

ブラウザーの一時的な選択と表示を通知します。選択ファイルは選択中の一覧に必要で、コンテキストは保存・エクスポートしません。

params: { workspaceId: string, activeEntryId: string | null, view: "preview" | "search" | "docs" }
result: null

markdown.setTask

登録済みMarkdownのタスクリストのチェックを1つ変更します。登録ファイルへ書き込む唯一の操作です。indexは文書順で0から数えたタスクの位置です。変更するのは括弧の中の1文字だけです。revisionは表示した内容の識別子で、表示後にファイルが変更されていた場合は書き込まず、競合のエラーを返します。シンボリックリンクの実体を原子的に置き換え、権限を維持します。

params: { workspaceId: string, id: string, index: number, checked: boolean, revision: string }
result: { revision }

review.list

エントリのコメントのスレッドを作成順に取得します。資料全体へのスレッドのanchorはnullです。

params: { workspaceId: string, entryId: string }
result: { threads: ReviewThread[] }

review.create

文章（anchor）または資料全体（null）に、最初のコメント付きのスレッドを作成します。attachmentsには1枚5MBまで、1コメント4枚までの画像を指定できます。

params: { workspaceId: string, entryId: string, anchor: TextAnchor | null, author: ReviewAuthor, body: string, attachments?: ReviewAttachmentUpload[] }
result: ReviewThread

review.reply

スレッドにコメントを追加します。review.createと同じく画像を添付できます。quoteを指定すると、スレッドを直した後の文章へ移します。quoteはファイルの表示される文字の中に1回だけ出てくる必要があり、空白は無視して照合します。LLMの返信は、quoteがなく、コメントした文章がファイルにない間はconflictで失敗します。

params: { threadId: string, author: ReviewAuthor, body: string, attachments?: ReviewAttachmentUpload[], quote?: string }
result: ReviewThread

review.resolve

スレッドを解決または再開します。

params: { threadId: string, resolved: boolean }
result: ReviewThread

review.request

エントリについて、LLMの会話に貼る依頼文を作成します。依頼文には、動いているzattoのCLIの絶対パスのコマンド（nodeとbin/zatto.js）を含むため、zattoにパスが通っていなくても実行できます。workspaceIdを--workspaceで渡すため、レビューはそのワークスペースで続きます。

params: { workspaceId: string, entryId: string }
result: { text: string }

review.start

エントリをLLMのセッションとのレビュー中にします。ユーザーが書いたコメントと返信は、そのセッション宛てに溜めます。同じエントリに別のセッションを選ぶとレビューを置き換えます。開始時には、未解決で最新のコメントがユーザーのもので、まだセッションが受け取っていないスレッドも溜めるため、レビュー前に書いたコメントも1回だけ届きます。

params: { workspaceId: string, entryId: string, session: string, client?: "claude" | "codex" }
result: ActiveReview

review.finish

レビューを終え、そのセッション宛てに終了のイベントを溜めます。

params: { reviewId: string }
result: null

review.states

レビュー中のエントリ、エントリごとの未解決と解決済みのスレッド数、スレッドごとにユーザーの最新のコメントをレビュー中のセッションが受け取ったか、最新のコメントがLLMの返信である未解決のスレッドを取得します。

params: {}
result: { reviews: ActiveReview[], openThreadCounts: Record<entryId, number>, resolvedThreadCounts: Record<entryId, number>, deliveries: Record<threadId, ReviewDelivery>, latestReplies: Record<threadId, ReviewLatestReply> }

review.take

セッション宛てに溜まったイベントを返して空にします。entryIdを指定すると、そのエントリのイベントだけを返します。レビューとイベントはサーバーのメモリーだけに持ちます。

params: { session: string, entryId?: string }
result: { events: ReviewEvent[] }

review.get

スレッドIDから、スレッドの全文と、スレッドを付けたファイル（ID・タイトル・絶対パス）を返します。ファイルは選択中でないワークスペースからも探します。

params: { threadId: string }
result: { thread: ReviewThread, file: { id, title, path } }

viewer.show

開いているWeb UIのタブに、/wsのviewer:showでエントリの表示を頼みます。/ws?client=viewerで接続したものだけをタブとして数えます。タブが開いていないとき、またはワークスペースが選択中でないときは通知せずshown: falseを返し、zatto reviewはブラウザーで開きます。

params: { workspaceId: string, entryId: string }
result: { shown: boolean }

search.query

登録済みHTMLソースを、大文字・小文字を区別しない固定文字列で検索します。workspaceIdを指定するとそのワークスペース、省略すると選択中のワークスペースが対象です。空文字は結果なし、検索語はUTF-16で256コード単位までです。ファイル数、件数、読取り量、応答量の上限を維持します。

params: { query: string, workspaceId?: string }
result: { query, totalMatches, truncated, files }

共通の結果型と交換形式

entries、added、resolvedの要素はEntryです。addedAtはミリ秒の時刻、favorite省略時はfalseです。filePickerとdirectoryPickerはPickerCapabilityです。AgentコンテキストはactiveFile（またはnull）とopenFilesにAgentContextFileを使います。検索の位置と一致範囲はUTF-16コード単位、lineNumberは1始まりです。

Entry

{ id: string, absPath: string, title: string, addedAt: number, favorite?: boolean }

WorkspaceState

{ activeWorkspaceId: string, workspaces: [{ id: string, name: string }] }

PickerCapability

{ available: boolean, instanceId?: string }

SessionExchange

{ format: "zatto-session", version: 1, entries: [{ path: string }] }

AgentContextFile

{ title: string, path: string }

TextAnchor

{ exact: string, prefix: string, suffix: string }

ReviewAuthor

{ kind: "user" } | { kind: "llm", session?: string, client?: "claude" | "codex" }

ReviewThread

{ id, entryId, anchor: TextAnchor | null, resolved: boolean, createdAt, comments: [{ id, author: ReviewAuthor, body, createdAt, attachments?: ReviewAttachment[] }] }

ReviewAttachment

{ id, name, type: "image/png" | "image/jpeg" | "image/webp" | "image/gif", path }

ReviewAttachmentUpload

{ name, type, data: base64 }

ReviewDelivery

{ entryId, status: "undelivered" | "delivered", since: number }

ReviewLatestReply

{ entryId, createdAt: number, client?: "claude" | "codex" }

ActiveReview

{ id, entryId, workspaceId, session, client?: "claude" | "codex", createdAt }

ReviewEvent

{ kind: "comment", reviewId, entryId, workspaceId, threadId } | { kind: "finished", reviewId, entryId, workspaceId }

SearchFileResult

{ entryId, title, fileName, absPath, matchCount, truncated, lines: SearchLineMatch[] }

SearchLineMatch

{ lineNumber, startOffset, lineText, truncated, ranges: [{ start, length }] }

交換パスは絶対パスで、正規化後に重複せず、読取り可能なHTMLまたはMarkdownである必要があります。タイトル、識別子、星は保存しません。次の要求は既存の識別子と星を保持して追加します。replaceではエントリを再生成し、星を解除します。

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "session.import",
  "params": {
    "instanceId": "server-instance-id",
    "workspaceId": "default",
    "mode": "merge",
    "exchange": {
      "format": "zatto-session",
      "version": 1,
      "entries": [
        {
          "path": "/path/to/page.html"
        }
      ]
    }
  }
}

エラー

操作の失敗はRESTのHTTPステータスではなくJSON-RPCのerrorへ返します。文言の比較ではなくerror.codeとerror.data.kindで判断します。

code意味 / data.kind
-32700Parse error
-32600Invalid Request
-32601Method not found
-32602Invalid params
-32603Internal error
1001notFound
1002workspace
1003instance
1004pickerUnavailable
1005busy
1006searchLimit
1007conflict
1008forbidden（外の端末に許していない操作）

検索の失敗は、SEARCH_QUERY_TOO_LONG、SEARCH_FILE_TOO_LARGE、SEARCH_FILE_READ_FAILEDなどの分類と、該当するentryId、maxLength、maxBytesをdataへ含めます。

notification / batch

idを省略したnotificationは、失敗時も応答せずログへ記録します。notificationのみの場合はHTTP 204です。batchは入力順に逐次実行し、失敗後も残りを処理します。全体のトランザクションにはせず、空配列は不正です。停止は単体またはbatchの応答を完了してから実行します。

ファイル配信とイベント

サーバーはすべての要求でHostヘッダーを検証し、ホスト名が127.0.0.1・localhost・[::1]以外の要求を403で拒否します。WS /wsは、Originヘッダーがあるときにhttp://のこれらのホスト名以外を403で拒否します。Originを付けない接続（Nodeからのzatto reviewなど）は受け付けます。

--hostで起動したサーバーは、ループバック以外のアドレスから届いた要求を外の端末として扱います。外の端末は、?token=に起動時のトークンを付けて開くとCookie（zatto_token、HttpOnly、SameSite=Strict）を受け取り、以降はそのCookieで認証します。トークンのない要求は401で拒否します。外の端末に許すRPCはserver.health、session.get、workspaces.list、workspaces.get、search.queryだけで、ほかはforbiddenで失敗します。結果の絶対パスはファイル名に置き換えます。/f/:idは選択中でないワークスペースのエントリも配信し、/review-attachments/:fileは403です。/wsはCookieとHostと同じOriginを必須とし、session:update（absPathはファイル名）とfile:changedだけを配信します。

GET /Web UI
GET /manifest.webmanifestWeb app manifest
GET /assets/*Frontend assets
GET /docs/*Built-in documentation / Changelog
GET /f/:id/Registered HTML preview
GET /f/:id/*Relative assets within the registered file root
GET /review-attachments/:fileレビューのコメントに添付した画像
WS /wssession:update / file:changed / review:update / review:states / review:event / viewer:show

サーバーはループバックで待ち受け、相対ファイルは登録基点の外へアクセスできません。RPC移行後もワークスペースの保存形式version 2と交換形式version 1を維持します。
