はじめに

複数のローカルHTMLとMarkdownのファイルを、1つのブラウザーセッションで閲覧します。

zattoを起動する

グローバルインストールせずに起動できます。ブラウザーが開き、コマンドの終了後もローカルサーバーは動作を続けます。

npx @yuske-nakajima/zatto

起動と同時に、1つ以上のファイルを追加することもできます。

npx @yuske-nakajima/zatto page.html report.html

ファイルを追加する

macOSでは、+ Add、Select HTML or Markdown files、またはCommand+Oを使います。既存の.html、.htm、.md、.markdownファイルを選択できます。

Markdown

Markdownファイルは閲覧専用で表示し、GitHub形式の表、タスクリスト、コードブロックに対応します。タスクリストのチェックだけはプレビューで切り替えられ、ファイルの[ ]または[x]だけを書き換えます。表示後にファイルが変更されていた場合は書き込まず、最新の内容を表示し直します。ライト・ダークのテーマはシステムの設定に従います。mermaidのコードブロックは図として描画し、構文エラーのある図にはエラーとソースを表示します。相対パスの画像とリンクはファイルのフォルダーを基点に解決し、Markdown内に書いたHTMLはそのまま表示します。最初のレベル1見出しをタイトルにし、見出しがない場合はファイル名を使います。テーマと図の描画処理は同梱しているため、通信は不要です。

Add folder…では、選択フォルダー直下または子孫を含むHTMLとMarkdownのファイルを追加できます。シンボリックリンクは無視し、登録済みパスは重複追加せず、相対パス順に追加します。

閲覧・検索する

  • ListまたはFoldersでファイルを選ぶと、プレビューを表示します。
  • フォルダー行には、子孫を含めて開いているファイル数を表示します。
  • プレビュー上部のゴミ箱ボタンで、選択中のファイルをセッションから外せます。
  • ファイルパネルの区切りをドラッグすると幅を変更できます。ダブルクリックすると既定の幅へ戻ります。
  • Searchでは、セッション内の全ファイルのソース（Markdownは原文）から固定文字列を検索できます。
  • 開いているファイルの変更は、プレビューと検索結果へ反映されます。

エントリやフォルダー行を削除しても、zattoのセッションから外れるだけです。ディスク上のファイルやフォルダーは削除しません。

セッションを保存・復元する

Export session…は、開いているファイルパスと表示順を保存します。Import session…では、一覧の全置換または未登録パスの追加を選択できます。

セッションJSONには絶対パスが入り、ローカルのアカウント名やディレクトリ名が含まれる場合があります。利用するコンピューター内で保管してください。

サーバーを停止する

npx @yuske-nakajima/zatto --stop

ワークスペースの選択

ファイルパネルのWorkspaceから名前付きのファイル群を作成・切り替え・名前変更・削除できます。ファイルパスとList順は再起動後も保存されます。単一セッション形式はDefaultへ移行します。選択は全タブとCLIで共有し、追加、インポート、エクスポート、Agentコンテキストは選択中を対象にします。切り替えで検索を解除し、List/Foldersとパネル設定は維持します。削除は確認付きで、実ファイルと最後の1件を残します。

お気に入り

List、Folders、Favoritesの各ファイル行にある星を使います。星はワークスペースごとに保存され、再起動後も残ります。Favoritesは通常Listの順序を保って星付きだけを表示します。星を外してもプレビューは維持します。並べ替えはListで操作し、全削除はListかFoldersへ戻って操作します。FavoritesではClear Allを無効にしています。キーボード、URL履歴、再読み込み、保存済み表示設定に対応します。検索は全ファイルが対象です。

コメント

プレビューで文章を選び、Commentを押すと、文書エディターのコメントのようにスレッドを立てられます。強調表示した文章をクリックするとスレッドが開き、Commentsにはファイル全体へのコメントや、文章が書き換わったスレッドを含めて一覧します。スレッドは返信、解決、再開ができ、ファイルを変更せずに別に保存します。図などを示すときは、コメントに画像を貼り付けるかドロップします。送信したコメントは編集・削除できないため、画像は送信前にプレビューから外します。LLMと資料について話すには、Ask an LLM to reviewを押してコピーした依頼文をLLMの会話に貼るか、LLMにファイルをレビュー中として登録してもらいます。ファイル一覧には未解決と解決済みのスレッド数を表示し、レビュー中はIn reviewを付けます。コメントした文章の行末の吹き出しから、スレッドを開き直せます。解決済みのスレッドは、チェック付きの薄い吹き出しで示します。書いたコメントや返信はその会話へ送られ、LLMがスレッドで答えます。LLMが受け取るまではNot delivered yetを、受け取ったあとは返答中のアニメーションを表示します。Finish reviewでレビューを終えます。

プレビューの中でリンクを開くと、登録済みのファイルはそのファイルを選んだ状態になります。未登録のページではNot in zattoとRegister・Backを表示し、文章を選ぶとRegister and commentで登録してそのページにコメントできます。リンク先のMarkdownも整形して表示し、チェックボックスは登録するまで操作できません。

3.0.0への更新

ファイルを変更・エクスポートするRPC操作で、対象ワークスペースのworkspaceIdが必須になり、サーバーの通信バージョンが4になります。パッケージを更新しても稼働中の2.xサーバーは動き続けるため、3.0.0のzatto --stopで停止してからzattoを起動します。停止するまで、3.0.0のCLIは2.xサーバーへ操作を送りません。ワークスペース、星、並び順と保存形式は引き継ぎます。

2.0.0への更新

操作通信はJSON-RPCへ移り、REST操作APIを廃止します。更新前はzatto --stopで旧サーバーを停止します。更新済みならnpx --yes @yuske-nakajima/zatto@1.2.0 --stopで旧サーバーを止め、新版のzattoを起動します。ワークスペース、星、順序、保存形式は引き継ぎます。DocsのChangelogで履歴を確認でき、ロゴの下にはインストール済みの版を表示します。

旧サーバーがruntime recordなしで独自ポートを使う場合は、旧版の停止コマンドへ--port <検出したポート>を付けます。新版CLIの診断メッセージは検出ポートを含む手順を示します。
