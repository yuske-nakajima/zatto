JSON-RPC API

All 32 operations use POST /rpc with application/json. REST operation routes are removed in 2.0.0. Static resources and WebSocket events retain their own transports.

Requests and responses

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "session.get",
  "params": {}
}
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "session.setFavorite",
  "params": {
    "id": "entry-id",
    "favorite": true,
    "workspaceId": "default"
  }
}
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": null
}

Use named object parameters. Omitted params mean an empty object. IDs may be strings, numbers or null; the response echoes the same ID and contains exactly one of result or error. Use ID-bearing requests whenever completion matters.

Target workspace and identity

Operations that change or export files require workspaceId, the workspace they act on. It may name any workspace, selected or not, and the selection does not change. An unknown or deleted workspace returns the workspace error. agentContext.set also requires workspaceId and rejects a workspace other than the selected one, because the browser context belongs to the selected workspace. Operations capture their target before asynchronous work.

Commands other than server.health accept an optional instanceId guard. Native pickers require instanceId, and import/shutdown require it for managed servers.

Methods

server.health

Identify the server and its protocol version.

params: {}
result: { name, version, instanceId?, protocolVersion? }

server.shutdown

Require a matching instance for a managed server; stop after the complete response.

params: { instanceId? }
result: { ok: true }

session.get

Read the active ordered collection and native-picker capabilities.

params: {}
result: { entries, activeWorkspaceId, workspaces, serverIdentity?, filePicker, directoryPicker }

session.add

Resolve paths and return requested existing/new entries once in argument order. Missing paths are skipped; read or save failure rejects the batch atomically. The endpoint does not require an HTML file extension.

params: { workspaceId: string, paths: string[] }
result: { added, resolved, workspaceId, activeWorkspaceId, session }

session.setFavorite

Set a persisted workspace star without reordering. An unchanged value performs no save or broadcast.

params: { workspaceId: string, id: string, favorite: boolean }
result: null

session.reorder

Supply every entry ID of the target workspace exactly once in the desired List order.

params: { workspaceId: string, ids: string[] }
result: null

session.removeMany

Remove a nonempty unique collection of known IDs atomically; leave disk files intact.

params: { workspaceId: string, ids: string[] }
result: null

session.remove

Remove one registered entry, leaving its disk file intact.

params: { workspaceId: string, id: string }
result: null

session.clear

Clear the target workspace collection without deleting disk files.

params: { workspaceId: string }
result: null

session.export

Return the target workspace as ordered absolute paths in the unchanged zatto-session exchange format.

params: { workspaceId: string }
result: SessionExchange version 1

session.import

Validate all paths before committing. Replace is the default and resets stars; merge preserves existing entries and stars. Managed servers require instanceId.

params: { workspaceId: string, exchange, mode?: "replace" | "merge", instanceId? }
result: { entries }

session.pickFiles

Open the native file picker. Require a matching instance; return cancellation without changes. Add to the target workspace.

params: { workspaceId: string, instanceId: string }
result: { cancelled, added, session? }

session.pickDirectory

Add HTML and Markdown files directly within a picked folder or recursively. Native pickers share one lock; symbolic links are not followed.

params: { workspaceId: string, instanceId: string, mode: "direct" | "recursive" }
result: { cancelled, added, session? }

workspaces.list

Read workspace names and the shared active selection.

params: {}
result: { activeWorkspaceId, workspaces: [{ id, name }] }

workspaces.get

Read one workspace and its entries in List order without changing the active selection. An unknown ID returns the workspace error.

params: { id: string }
result: { id, name, entries }

workspaces.create

Create an empty workspace without changing selection. A trimmed name has 1–100 characters.

params: { name: string }
result: { id, name }

workspaces.activate

Persist and broadcast the active selection; browser search and preview state follow workspace-change rules.

params: { id: string }
result: { entries, activeWorkspaceId, workspaces }

workspaces.rename

Rename a workspace without changing its files or ID.

params: { id: string, name: string }
result: { activeWorkspaceId, workspaces }

workspaces.delete

Remove a workspace while retaining disk files and at least one workspace. If active, select the first remaining workspace.

params: { id: string }
result: { entries, activeWorkspaceId, workspaces }

agentContext.get

Read titles and absolute paths, not HTML contents. Titles are untrusted labels, normalized and limited to 200 Unicode code points.

params: {}
result: { schemaVersion: 1, activeFile, openFiles, view }

agentContext.set

Update transient browser context. A selected file must exist in the active workspace; context is not persisted or exported.

params: { workspaceId: string, activeEntryId: string | null, view: "preview" | "search" | "docs" }
result: null

markdown.setTask

Set one task list checkbox in a registered Markdown file, the only operation that writes to a registered file. index is the zero-based task position in document order. Only the character between the brackets changes. revision identifies the content the page was rendered from; when the file changed since then, nothing is written and the conflict error is returned. The real path behind a symbolic link is replaced atomically and keeps its permissions.

params: { workspaceId: string, id: string, index: number, checked: boolean, revision: string }
result: { revision }

review.list

Read the comment threads of an entry in creation order. anchor is null for whole-document threads.

params: { workspaceId: string, entryId: string }
result: { threads: ReviewThread[] }

review.create

Start a thread on text (anchor) or the whole document (null) with its first comment. attachments are images of up to 5 MB each, at most 4 per comment.

params: { workspaceId: string, entryId: string, anchor: TextAnchor | null, author: ReviewAuthor, body: string, attachments?: ReviewAttachmentUpload[] }
result: ReviewThread

review.reply

Add a comment to a thread, optionally with images as in review.create. quote moves the thread to edited text, which must appear once in the file's visible text; whitespace is ignored. An LLM reply without quote fails with conflict while the commented text is missing from the file.

params: { threadId: string, author: ReviewAuthor, body: string, attachments?: ReviewAttachmentUpload[], quote?: string }
result: ReviewThread

review.resolve

Resolve or reopen a thread.

params: { threadId: string, resolved: boolean }
result: ReviewThread

review.request

Build the request to paste into an LLM conversation for an entry. It contains the absolute command of the running zatto CLI (node and bin/zatto.js), so it runs without zatto on PATH.

params: { workspaceId: string, entryId: string }
result: { text: string }

review.start

Put an entry under review with an LLM session. Comments and replies the user writes on it are queued for that session. Choosing another session for the same entry replaces the review. Starting also queues each unresolved thread whose latest comment is the user's and that the session has not taken yet, so comments written before the review reach it once.

params: { workspaceId: string, entryId: string, session: string, client?: "claude" | "codex" }
result: ActiveReview

review.finish

End a review and queue a finished event for its session.

params: { reviewId: string }
result: null

review.states

Read the entries under review, unresolved and resolved thread counts per entry, whether the reviewing session took the user's latest comment on each thread, and the newest LLM reply per entry.

params: {}
result: { reviews: ActiveReview[], openThreadCounts: Record<entryId, number>, resolvedThreadCounts: Record<entryId, number>, deliveries: Record<threadId, ReviewDelivery>, latestReplies: Record<entryId, ReviewLatestReply> }

review.take

Return and clear the events queued for a session; with entryId, only that entry's events. Reviews and events are kept only in server memory.

params: { session: string, entryId?: string }
result: { events: ReviewEvent[] }

search.query

Search registered HTML source using a case-insensitive fixed string. An empty query returns no matches; query length is at most 256 UTF-16 code units. File, match, byte and response limits remain enforced.

params: { query: string }
result: { query, totalMatches, truncated, files }

Reusable result and exchange types

entries and added/resolved contain Entry objects. addedAt is a millisecond timestamp; absent favorite means false. filePicker and directoryPicker use PickerCapability. Agent context uses AgentContextFile for activeFile (or null) and openFiles. Search file/line offsets and range lengths use UTF-16 code units; lineNumber is one-based.

Entry

{ id: string, absPath: string, title: string, addedAt: number, favorite?: boolean }

WorkspaceState

{ activeWorkspaceId: string, workspaces: [{ id: string, name: string }] }

PickerCapability

{ available: boolean, instanceId?: string }

SessionExchange

{ format: "zatto-session", version: 1, entries: [{ path: string }] }

AgentContextFile

{ title: string, path: string }

TextAnchor

{ exact: string, prefix: string, suffix: string }

ReviewAuthor

{ kind: "user" } | { kind: "llm", session?: string, client?: "claude" | "codex" }

ReviewThread

{ id, entryId, anchor: TextAnchor | null, resolved: boolean, createdAt, comments: [{ id, author: ReviewAuthor, body, createdAt, attachments?: ReviewAttachment[] }] }

ReviewAttachment

{ id, name, type: "image/png" | "image/jpeg" | "image/webp" | "image/gif", path }

ReviewAttachmentUpload

{ name, type, data: base64 }

ReviewDelivery

{ entryId, status: "undelivered" | "delivered", since: number }

ReviewLatestReply

{ threadId, createdAt: number, client?: "claude" | "codex" }

ActiveReview

{ id, entryId, workspaceId, session, client?: "claude" | "codex", createdAt }

ReviewEvent

{ kind: "comment", reviewId, entryId, workspaceId, threadId } | { kind: "finished", reviewId, entryId, workspaceId }

SearchFileResult

{ entryId, title, fileName, absPath, matchCount, truncated, lines: SearchLineMatch[] }

SearchLineMatch

{ lineNumber, startOffset, lineText, truncated, ranges: [{ start, length }] }

Exchange paths must be absolute, unique after normalization, readable HTML or Markdown files. No title, ID or favorite flag is stored. The following request merges an exchange document without changing existing IDs or stars; replace regenerates entries and clears stars.

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "session.import",
  "params": {
    "instanceId": "server-instance-id",
    "workspaceId": "default",
    "mode": "merge",
    "exchange": {
      "format": "zatto-session",
      "version": 1,
      "entries": [
        {
          "path": "/path/to/page.html"
        }
      ]
    }
  }
}

Errors

Expected failures use JSON-RPC error envelopes, not REST HTTP status codes. Inspect error.code and error.data.kind rather than matching message text.

-32700Parse error
-32600Invalid Request
-32601Method not found
-32602Invalid params
-32603Internal error
1001notFound
1002workspace
1003instance
1004pickerUnavailable
1005busy
1006searchLimit

Search failures may include a specific code such as SEARCH_QUERY_TOO_LONG, SEARCH_FILE_TOO_LARGE or SEARCH_FILE_READ_FAILED and applicable entryId/maxLength/maxBytes details.

notification / batch

A notification omits id and produces no response even on failure; failures are logged. A notification-only request returns HTTP 204. A batch runs sequentially in input order; failures do not stop remaining calls and the batch is not a transaction. An empty array is invalid. Shutdown waits until the complete single or batch response has been sent.
