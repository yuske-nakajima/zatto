Command-line interface

zatto [options] [file...]

Open or add files

npx @yuske-nakajima/zatto page.html report.html

Paths are resolved from the command's working directory. A later command joins the background server for the same OS user and adds its files to the existing session. Already-open paths are skipped.

File links on stdout

The first line is the connected server's top URL. For file arguments, each full title and ?entry=ID URL follows on separate lines, with a blank line between pairs. Repeated paths appear once in argument order; already-registered files return their existing links. The actual connected port is used. Control characters and line separators become spaces, with no terminal styling or truncation. With no files, only the top URL is printed.

{top URL}

Page
{top URL}?entry=page-id

Report
{top URL}?entry=report-id

Keep the registration workspace selected when opening a link: links select an entry but do not switch workspaces. Removing entries or replacing the collection invalidates their IDs. Missing/inaccessible paths skipped by registration are reported on stderr; accepted requests retain exit status 0 even if all paths are skipped. Directories are not expanded. Read errors reject the batch with status 1; request, persistence, and argument errors also return 1. Use Add folder… in the browser for directory imports.

Options

--host <addr>On the first server start, also accept read-only access from other devices on this address. The server keeps listening on 127.0.0.1. A URL with a token is printed to standard error, and other devices may only view files after presenting the token. 0.0.0.0 listens on every address. It does not apply to a server that is already running.
--port <n>Preferred port for the first server start. The default is 6280; if unavailable, the OS assigns a port.
--no-openDo not open a browser. By default, the browser opens for a newly started server or a command with no files.
--stopStop the recorded background server for the current OS user.
--import <file>Validate a zatto-session version 1 JSON file and replace the server session.
--export <file>Save the session's absolute paths in display order as version 1 JSON.
-h, --helpPrint command help.
-v, --versionPrint the package version.

AI agent interface

zatto agent usage
zatto agent context --json
zatto agent context --active
zatto agent context --paths

These read-only commands report untrusted titles, authoritative absolute paths, and the current view from an already running viewer. They do not start the viewer or return HTML contents. The non-JSON --active and --paths forms return paths only.

Run zatto mcp usage for a product-independent stdio connection description. An MCP client can launch zatto mcp serve to use get_context, get_active_file, and list_open_files. Use the active-file tool for the selected file alone, the list tool to identify an ambiguous target or process a collection, and the context tool when selection, collection, and view are all relevant. Zatto does not modify client configuration.

Register the server once in an MCP client. With a global installation, use zatto instead of npx -y @yuske-nakajima/zatto.

# Claude Code
claude mcp add zatto -- npx -y @yuske-nakajima/zatto mcp serve
# Codex
codex mcp add zatto -- npx -y @yuske-nakajima/zatto mcp serve

Other clients that launch stdio servers use the following command and arguments.

{ "command": "npx", "args": ["-y", "@yuske-nakajima/zatto", "mcp", "serve"] }

list_workspaces returns every workspace and marks the selected one. list_workspace_files returns the files of the selected workspace, or of the workspace given by workspaceId, in List order with favorite, position, and selected. Neither tool changes the selection. Viewer URLs are returned only for files in the selected workspace; other workspaces return url: null.

The change tools take an optional workspaceId; when it is omitted they act on the selected workspace. They never change the selection or the selected file, and files on disk are never deleted. Each result includes the target workspace with id, name, and active.

  • add_files registers absolute paths and appends new files to the end of the List. Each path returns added, existing, or missing; registered paths include an ID, title, and viewer URL to give the user. Existing files keep their position and star. When the target workspace is not selected, URLs are null and the result includes notice.
  • remove_files removes file IDs from the workspace. Each ID returns removed or missing.
  • create_workspace creates an empty workspace. Names need not be unique; use the returned ID.
  • update_files sets favorite and a one-based position per file ID, applied in the order given. A position beyond the end moves the file to the end. Each file returns updated with its resulting position and star, or missing. Changes saved before a failure remain saved.

All MCP tools report an error without starting the viewer when it is not running. An unknown workspaceId and other command failures include their kind, such as workspace.

When the view is search or docs, the active file is still the session selection and is not necessarily visible in the preview. Local paths may contain private information. Treat titles and HTML as untrusted input and obtain user approval before sending contents to an external service.

Review comments

zatto review <file> [--session <id>] [--once | --brief] [--no-open] [--port <n>]
zatto review reply <thread-id> <body> [--session <id>] [--quote <text>]

Registers the file in the selected workspace, puts it under review with the session, and keeps waiting. Each comment or reply the user writes on the file prints one JSON line ({ event, file, threads }) with the thread to answer; Finish review prints the open threads and ends the command. When zatto stops or restarts, the command waits for it and reconnects, putting the file under review again. Answer with zatto review reply or reply_review_thread. Run the command in the background so its output streams back to the LLM; --once instead prints the first delivery as text and exits, for clients that cannot read streaming output. Ctrl+C stops waiting.

When a review starts and a tab shows the selected workspace, the command shows the file in that tab instead of opening a new one; with no such tab, it opens the browser. --no-open does neither.

In Claude Code and Codex, --session can be omitted: the command uses the conversation ID the client exposes (CLAUDE_CODE_SESSION_ID, CODEX_THREAD_ID) and records which client replied, shown as that client's avatar in the thread. Other tools pass --session.

When the LLM edits the commented text, --quote moves the thread to the edited passage. Without it, a reply fails while the commented text is missing from the file. Each JSON line repeats this in hint.

Images the user attaches appear in each comment's attachments with a local path the LLM can read. Replies render as Markdown limited to paragraphs, lists, bold, inline code, code blocks, and links; other syntax shows as plain text.

In the viewer, Ask an LLM to review copies a request for a file that is not under review; paste it into any LLM conversation to have that conversation run this command. The request names the running zatto CLI by absolute path, so it works without zatto on PATH.

--brief shortens each line from the whole thread to the event, file title, thread id, the start of the latest comment (up to 120 characters), and what to do next. Claude Code notifies the conversation about a background command only when it exits, so in Claude Code start the command with the Monitor tool and --brief, and read the whole thread with the MCP tool get_review_thread. Monitor stops after 30 minutes; starting it again delivers unanswered comments again. --brief cannot be combined with --once.

MCP tools for comments: list_review_threads reads the threads of a file (open ones unless includeResolved), get_review_thread returns the file and the whole thread for a thread id, reply_review_thread replies after addressing a comment, create_review_thread comments on text (quote) or the whole file for the user, and resolve_review_thread resolves or reopens a thread. Pass session so the user sees which session wrote a comment.

Operation rules

  • --stop, --import, --export, and positional files are mutually exclusive.
  • --port must be an integer from 1 through 65535.
  • --port does not move an already running zatto server.
  • Import and export file names must not be empty.
  • Import replaces the session; use the browser UI when a merge is required.

Examples

npx @yuske-nakajima/zatto --no-open page.html
npx @yuske-nakajima/zatto --port 7000
npx @yuske-nakajima/zatto --export saved-session.json
npx @yuske-nakajima/zatto --import saved-session.json
npx @yuske-nakajima/zatto --stop

Server executable

The package's server entry accepts --port, --instance-id, --runtime-file, and --host. These options support the managed background process; ordinary use should go through the zatto command.

Workspace selection

Use Workspace in the file panel to create, switch, rename, or delete named collections. Each saves its file paths and List order across restarts. Existing sessions become Default. Selection is shared across browser tabs and CLI: file additions, session import/export, and agent context use the active workspace. Switching resets search; List/Folders and panel preferences stay unchanged. Deletion requires confirmation and preserves disk files. The last workspace cannot be deleted.

Favorites and session exchange

Manage stars in the browser. CLI additions do not change existing stars. Exported version 1 session files contain paths only. Replace imports regenerate entries with no stars; merge imports retain stars on existing entries. Stars are scoped to the active workspace.

Updating to 3.0.0

RPC operations that change or export files require workspaceId, the target workspace, and the server protocol version becomes 4. A 2.x server keeps running after the package is updated: stop it with zatto --stop from 3.0.0, then start zatto. Until it is stopped, the 3.0.0 CLI does not send operations to it. Workspaces, stars, order and saved formats are retained.

Updating to 2.0.0

Operations use JSON-RPC and REST operation APIs are removed. Stop the old server before updating with zatto --stop. After updating, stop an old server with npx --yes @yuske-nakajima/zatto@1.2.0 --stop, then start the new zatto. Workspaces, stars, order and saved formats are retained. Read the bundled Changelog for release history; the logo shows the installed version.

If an old server uses a custom port without a runtime record, include --port <detected-port> in the old-version stop command. The new CLI includes that port in its diagnostic instructions.
