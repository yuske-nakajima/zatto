Getting started

Open local HTML and Markdown files together in one browser session.

Start zatto

Run zatto without installing it globally. A browser window opens and the local server remains available after the command exits.

npx @yuske-nakajima/zatto

You can also add one or more files as the viewer starts.

npx @yuske-nakajima/zatto page.html report.html

Add files

On macOS, use + Add, Select HTML or Markdown files, or Command+O. The picker accepts existing .html, .htm, .md, and .markdown files.

Markdown

Markdown files are shown read-only with GitHub-flavored tables, task lists, and code blocks. Task list checkboxes can be toggled in the preview, which writes only that [ ] or [x] back to the file; if the file changed since it was shown, nothing is written and the latest content is shown. The light or dark theme follows the system setting. A mermaid code block is drawn as a diagram; a diagram with a syntax error shows the error and its source. The ⤢ button that appears when you hover over a diagram redraws it to fill the preview; Esc or × returns. While a Markdown file is shown, ⇤⇥ in the header switches between a readable width of up to 980px and the full width of the preview. The choice is remembered in this browser and used for every Markdown file. Relative images and links resolve from the file's folder, and HTML written in Markdown is shown as written. The first level-one heading becomes the title; without one, the file name is used. Themes and the diagram renderer are bundled, so no network connection is needed.

Use Add folder… to add either the HTML and Markdown files directly inside a folder or all of them in its descendants. Symbolic links are ignored, registered paths are not added twice, and files are ordered by relative path.

Browse and search

  • Choose a file in List or Folders to show its preview.
  • Folder rows show the number of open files in their subtree.
  • Use the trash button in the preview header to remove the selected file from the session.
  • Drag the file-panel divider to resize it; double-click the divider to restore its default width.
  • Use Search to find fixed text across the source of every session entry, including Markdown source.
  • Changes to an open file refresh its preview and search results.

Removing an entry or folder row only changes the zatto session. It never deletes files or folders from disk.

Save or restore a session

Export workspace… saves the file paths of the selected workspace and their order. Import workspace… can replace the list or merge paths that are not already open.

Session JSON contains absolute paths and can reveal local account or directory names. Keep it on the computer where it is used.

Stop the server

npx @yuske-nakajima/zatto --stop

Workspace selection

Use Workspace in the file panel to create, switch, rename, or delete named collections. Each saves its file paths and List order across restarts. Existing sessions become Default. Selection is shared across browser tabs and CLI: file additions, session import/export, and agent context use the active workspace. Switching resets search; List/Folders and panel preferences stay unchanged. Deletion requires confirmation and preserves disk files. The last workspace cannot be deleted.

Favorites

Use each file row's star in List, Folders, or Favorites. Stars are saved per workspace across restarts. Favorites filters the full List without changing its order. Unstarring a file keeps its preview open. Reorder in List; Clear All is disabled in Favorites, so use List or Folders to clear the whole workspace. Keyboard activation, browser history, reload, and saved panel preferences are supported. Search includes all workspace files.

Comments

Select text in the preview and press Comment to start a thread, like comments in a document editor. Highlighted text opens its thread; Comments lists every thread of the file, including whole-document comments and threads whose text was rewritten. Threads can be replied to, resolved, and reopened, and are kept separately from the file without changing it. Paste or drop images into a comment to point at a figure; sent comments cannot be edited or deleted, so remove an image from the preview before sending. To discuss a file with an LLM, press Ask an LLM to review and paste the copied request into an LLM conversation, or let the LLM register the file for review. The file list shows each file's unresolved and resolved thread counts, marked In review while the file is under review. A bubble at the end of commented text reopens its thread; resolved threads show a faint bubble with a check. Threads read like a chat: your comments on the right, LLM replies on the left with an avatar for Claude, Codex, or another LLM, each with its date and time, and code blocks in replies have a Copy button. Each comment or reply you write is sent to that conversation, which answers in the thread; the thread shows Not delivered yet until the LLM takes the comment, then an animation while it replies. Finish review ends the review.

⤢ in a thread header expands the thread to fill the preview area. Esc closes one thing at a time, in this order: an enlarged image, page search, the expanded size, then the thread. It works while focus is in the preview text and is ignored while composing text with an input method.

Hovering a paragraph, list item, heading, table row, or code block shows a bubble in the left margin that comments on the whole block without selecting text. Comments lists threads with the most recent activity first and marks replies you have not opened, remembered in this browser. The status bar tells what reviewing LLMs are doing: thinking about a comment, a reply you have not opened (click to go to its thread, even in another file), or how many files are under review. With several unseen replies it shows how many threads have one, and hovering it lists the files with their counts; choosing one opens that file with its Comments list. A thread scrolled out of view does not count as read.

Following a link in the preview opens a registered file as the selected file. An unregistered page shows Not in zatto with Register and Back; selecting text there offers Register and comment, which registers the page and opens a comment on it. Linked Markdown pages are rendered, with checkboxes left read-only until the page is registered.

Updating to 3.0.0

RPC operations that change or export files require workspaceId, the target workspace, and the server protocol version becomes 4. A 2.x server keeps running after the package is updated: stop it with zatto --stop from 3.0.0, then start zatto. Until it is stopped, the 3.0.0 CLI does not send operations to it. Workspaces, stars, order and saved formats are retained.

Updating to 2.0.0

Operations use JSON-RPC and REST operation APIs are removed. Stop the old server before updating with zatto --stop. After updating, stop an old server with npx --yes @yuske-nakajima/zatto@1.2.0 --stop, then start the new zatto. Workspaces, stars, order and saved formats are retained. Read the bundled Changelog for release history; the logo shows the installed version.

If an old server uses a custom port without a runtime record, include --port <detected-port> in the old-version stop command. The new CLI includes that port in its diagnostic instructions.
