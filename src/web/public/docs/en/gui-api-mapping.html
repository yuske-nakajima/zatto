GUI and API mapping

The browser UI is a client of the same local server. This table shows the request behind each visible action.

GUI behaviorServer operationResult in the UI
Open the viewerGET /api/sessionLoads ordered entries, server identity, and picker availability.
Select a fileGET /f/:id/Loads the HTML in the preview iframe; relative resources use GET /f/:id/*.
Open a Docs pageGET /docs/*Loads the selected locale and slug in a same-origin iframe without creating a session entry.
Receive session or file changesWS /wsUpdates the file panel, preview, and search state.
Search HTML filesGET /api/searchShows fixed-string source matches and truncation status.
Select HTML filesPOST /api/session/pickOpens the native file dialog and selects the first added entry.
Add folder…POST /api/session/pick-directoryUses the selected direct or recursive scope and selects the first added entry.
Drag entries to reorderPATCH /api/session/orderPersists the complete display order.
Remove one file from its row or previewDELETE /api/session/:idRemoves the selected session entry without deleting its file.
Remove a folder rowDELETE /api/session/entriesAtomically removes every session entry in that subtree.
Clear sessionDELETE /api/sessionRemoves all session entries after confirmation.
Import session…PUT /api/sessionReplaces entries or merges unregistered paths according to the chosen mode.
Export session…GET /api/session/exportDownloads display order or a path-sorted copy without changing the session.
Change selection or main viewPUT /api/agent/contextReports volatile path and view context for read-only agent clients.

Operations without a direct GUI control

POST /api/session/add is used by the CLI to add path arguments. GET /api/health identifies a compatible server, and POST /api/shutdown supports the stop command.

Docs are built-in content. They do not become session entries and are excluded from List, Folders, HTML search, import, export, removal, and ordering.
